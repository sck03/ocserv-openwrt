# 仅 VPN 用户使用 OpenClash、Nikki 或 Momo

适用于 Phicomm N1 / OpenWrt 25.12 的单网口旁路由：N1 接在主路由 LAN 内，普通电脑通过主路由正常上网。

## 使用

1. 全新安装 ocserv 1.6.0 或后续版本，让客户端能够正常登录；配置并开启 OpenClash、Nikki、Momo 中的一款代理。多款同时启用时会提示先解决冲突。
2. LuCI → VPN → 岚序 Lansyra → **VPN 专用上网**。
3. 点击 **开启**，查看本次说明并确认。页面显示识别到的代理、实际 N1 地址、当前管理电脑 IPv4 和 VPN 网段。
4. 稍候，状态变为 **已开启**。以后点击 **关闭并恢复** 即可恢复启用前的相关设置。

开关默认关闭。安装服务端不会自动开启这个模式。切换时可能短暂重启相关服务，VPN 客户端需要重连。

**不开启时也可以使用代理**：管理页 0.6.3 修复自动接入的启动事件，在 ocserv、Nikki 或 Momo 启动后为 VPN 接入代理与 DNS，保留原来的普通 LAN 代理设置。该接入由 procd 内部 `instance.update` 事件触发，合并三秒内的事件；管理服务自身启动时也会补做一次。无需额外开关或常驻代理轮询。首次接入、更改 VPN 网段或代理升级后可能重启代理一次；重复事件不重写配置或暂存文件。开启本页开关后才限制只有 VPN 连接者可使用 N1 的代理，并阻止普通 LAN 改网关、DNS 或手填代理端口绕过限制。

如果普通 VPN 只能访问国内网站，先点击 **检查代理**。Nikki/Momo 的 VPN 入口需要包含 `vpns*`，访问控制需要覆盖实际 VPN 地址池；只显示代理进程运行不能确认接入。透明代理使用生成规则中的 Redirect/TPROXY/DNS 端口，不使用 HTTP/SOCKS 的 mixed-port 代替。Momo 还需要有效的 sing-box JSON；Clash YAML 订阅不能直接作为 Momo 配置使用，新增订阅须先保存再更新。

管理页 0.6.4 使用 procd 的服务归属核对核心，避免把 Nikki 的 Mihomo 误认成 OpenClash；停止的服务不再显示其他软件共用的 TUN。三款代理的隔离启用检查等待有效 DNS 重定向目标和实际 TCP/UDP 监听，Nikki/Momo 还需 VPN 接口集合。后台普通接入同样检查 Nikki/Momo 的规则和监听。切换期间服务和防火墙会重建，待状态完成后重新连接 VPN。

本轮 N1 的 Nikki/Momo 与 OpenClash 三阶段流量检查均通过。此前 OpenClash 的 TLS 提前关闭已定位到冷启动时大型规则提供器尚未初始化完成：同一配置等待加载后自动恢复，嗅探开启也通过。启动后先等待规则提供器完成，再用 VPN 客户端验证外网；进程、监听、内部测速或 `Initial configuration complete` 不能证明完整转发就绪。当前管理页检查仍侧重规则和监听，本轮未修改其就绪逻辑。具体证据和恢复状态见[验证记录](VALIDATION.md)。

| 访问方式 | 开启后的行为 |
|---|---|
| 普通电脑通过主路由上网 | 保持原有行为 |
| 未登录 VPN，把网关或 DNS 改为 N1 | 不能借 N1 转发或解析 |
| 未登录 VPN，手填 N1 的 HTTP/SOCKS/自定义代理端口 | 拦截 |
| LAN 伪造 VPN 地址池来源 | 拦截 |
| 正常登录 ocserv | VPN 流量交给所选代理的现有规则处理 |
| 当前管理电脑访问 SSH/LuCI | 保留（包含检测到的自定义管理端口） |

## 开关会处理什么

- 在代理接管前，对真实 LAN 和 `vpns*` 入接口应用独立 nftables 表；授权依据为 VPN 接口，不只是源地址白名单。
- 设置 ocvpn 防火墙区域和到 LAN 上游的转发，按当前 VPN 地址池配置源 NAT。
- 推送全部流量路由，DNS 指向 IPv4 隧道服务端地址；由代理的防火墙 DNS 重定向将 VPN 查询送入核心，不改写 dnsmasq 的监听和上游配置。
- 将 OpenClash LAN 访问控制设为 VPN 地址池白名单，移除 MAC 白名单限制；Fake-IP 模式会使用 OpenClash 要求的防火墙 DNS 重定向（`enable_redirect_dns=2`），关闭时恢复原值。订阅、节点、代理模式和分流规则保持不变。
- Nikki/Momo 启用 LAN 代理及 IPv4 DNS 接管；暂时停用原 LAN 访问控制项，新增 VPN 地址池允许项。入口使用 `vpns*` 接口集合，覆盖新连接和重连；关闭时恢复原访问控制及顺序，不新增常驻接口轮询。
- 暂时关闭 fw4 的软件/硬件流量卸载。若检测到额外 SFE/快捷转发内核模块，会在修改前停止并提示关闭该加速。

此模式在隧道内提供 IPv4 VPN，阻止通过 N1 的 IPv6 绕过。外层 VPN 连接可使用公网 IPv6，入口只开放 VPN 端口和必要的 IPv6 控制报文。它不限制电脑直接使用主路由或其他独立代理服务。公网部署见[域名与公网连接](WAN.md)。

## 自动恢复

### 查看服务日志

在“VPN 专用上网”页点击 **查看日志**，可查看启用、配置校验、防火墙应用、所选代理和 ocserv 重启、管理连接确认及恢复的步骤。失败时记录步骤、退出码、等待超时以及可识别的常见错误类型；点击 **刷新日志** 获取最新记录。日志窗口打开期间仍会继续确认管理连接。

日志仅保留最近 **24 小时**，最多 **256 条**，由独立后台清理进程自动删除过期记录，无需保持网页打开，关闭功能或恢复失败后也会清理。日志存放于 `/var/run/ocserv-easy/guard-log.json`，仅 root 可读，设备重启后清空；已登录且具备此管理页读取权限的用户可通过页面查看。日志不保存命令的原始输出、账号、密码、订阅或配置文件内容，只提取常见错误类型。旧版本的故障不能补录。

服务重启命令成功返回后，会等待最多 10 秒确认 ocserv 进程启动，避免将 procd 的异步启动误判为失败。超过等待时间仍会记录失败并执行恢复。

后台进程完成应用后进入待确认阶段。页面只有在新的、经过登录认证的管理请求成功返回后才发送确认，而且确认绑定当前管理电脑地址。未在约两分钟内完成确认，会尝试自动恢复。

失败、重启或断电留下的未确认事务也会恢复；开机恢复安排在 fw4 启动之前。事务截止时间使用设备单调运行时间，系统 NTP 校时不会提前或延后恢复。关闭时只还原本功能记录的配置项和文件，保留后来新增的账号及其他已提交改动。若其他页面有未应用的修改，恢复会保留记录并提示重试，避免丢弃那些修改。

备份和事务记录位于 `/etc/ocserv/easy-guard`，仅 root 可读；其中可能包含配置中的敏感内容，不要作为诊断附件公开。恢复失败时，页面可再次选择“关闭并恢复”。SSH 恢复命令：

```sh
/usr/bin/lua /usr/libexec/ocserv-easy-guard disable
```

模式开启期间，服务设置页暂时禁止更改 VPN 网络参数。可继续管理账号；需要改地址池、DNS或端口时，先关闭本模式，调整后再开启。

## 适用范围

代理登记表 `proxy_registry.lua` 统一维护软件名、服务身份与适配能力，事务包列表、权限检查和恢复校验均读取该表。OpenClash、Nikki、Momo 已有接入适配；PassWall、PassWall 2、HomeProxy、SSR Plus+ 目前可以检测其 procd 运行实例并提示尚未适配，同时运行会提示冲突。检测到进程不代表支持自动接入或隔离，不会套用另一款软件的配置。没有 procd 实例的软件需要专门的归属检测器。

增加代理时，先登记身份，再实现该软件的模式校验、VPN 入口和 DNS 接入、运行规则就绪检查、可恢复的配置计划；同时更新 rpcd ACL 和打包审计，补充开启/关闭、外部修改保护和真实软件报文验证。nftables 的隔离表与软件无关，软件专有配置仍需明确的适配配方。这样可以复用隔离和事务模块，而无需为每款软件复制恢复逻辑。

需要 fw4、dnsmasq、工作中的 ocserv 1.6.0+ 和一款已配置的代理。OpenClash 支持 Clash 与 Meta/Mihomo 内核；Nikki/Momo 需要完整代理模式，TCP 使用 redirect、tproxy 或 tun，UDP 使用 tproxy 或 tun。从同一 LAN 的 IPv4 管理地址开启；检测到活跃 WAN 的主路由不应用此旁路由规则。地址池必须填写网络地址。本版按全新安装重新配置，不复用旧规则或事务目录。

Nikki/Momo 的上游入口只接受 OpenWrt 逻辑接口，无法直接描述 ocserv 后续生成的接口。本功能在事务中精确修改 `/etc/nikki/ucode/hijack.ut` 或 `/etc/momo/ucode/hijack.ut` 的入口数组；模板结构不匹配时拒绝启用，重启后还会检查实际 nft 接口集合。**升级或重装 Nikki/Momo、切换代理前，先关闭本开关；完成后再开启。** 模板被外部修改时不会强制覆盖，恢复结果会提示保留了外部修改。
