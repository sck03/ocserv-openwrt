# 仅 VPN 用户使用 OpenClash

适用于 Phicomm N1 / OpenWrt 25.12 的单网口旁路由：N1 接在主路由 LAN 内，普通电脑通过主路由正常上网。

## 使用

1. 先让 ocserv 客户端能够正常登录，并让 OpenClash 使用现有订阅正常运行。
2. LuCI → VPN → OpenConnect VPN → 布利杰VPN → **VPN 专用上网**。
3. 点击 **开启**，查看本次说明并确认。页面显示实际 N1 地址、当前管理电脑 IPv4 和 VPN 网段。
4. 稍候，状态变为 **已开启**。以后点击 **关闭并恢复** 即可恢复启用前的相关设置。

开关默认关闭。安装服务端不会自动开启这个模式。切换时可能短暂重启相关服务，VPN 客户端需要重连。

| 访问方式 | 开启后的行为 |
|---|---|
| 普通电脑通过主路由上网 | 保持原有行为 |
| 未登录 VPN，把网关或 DNS 改为 N1 | 不能借 N1 转发或解析 |
| 未登录 VPN，手填 N1 的 HTTP/SOCKS/自定义代理端口 | 拦截 |
| LAN 伪造 VPN 地址池来源 | 拦截 |
| 正常登录 ocserv | VPN 流量交给 OpenClash 的现有规则处理 |
| 当前管理电脑访问 SSH/LuCI | 保留（包含检测到的自定义管理端口） |

## 开关会处理什么

- 在 OpenClash 接管前，对真实 LAN 和 `vpns*` 入接口应用独立 nftables 表；授权依据为 VPN 接口，不只是源地址白名单。
- 设置 ocvpn 防火墙区域和到 LAN 上游的转发，按当前 VPN 地址池配置源 NAT。
- 推送全部流量路由，DNS 指向隧道服务端地址；由 OpenClash 的防火墙 DNS 重定向将 VPN 查询送入核心，不改写 dnsmasq 的监听和上游配置。
- 将 OpenClash LAN 访问控制设为 VPN 地址池白名单，移除 MAC 白名单限制；Fake-IP 模式会使用 OpenClash 要求的防火墙 DNS 重定向（`enable_redirect_dns=2`），关闭时恢复原值。订阅、节点、代理模式和分流规则保持不变。
- 暂时关闭 fw4 的软件/硬件流量卸载。若检测到额外 SFE/快捷转发内核模块，会在修改前停止并提示关闭该加速。

此模式提供 IPv4 VPN，阻止通过 N1 的 IPv6 绕过。它不限制电脑直接使用主路由或其他独立代理服务。

## 自动恢复

后台进程完成应用后进入待确认阶段。页面只有在新的、经过登录认证的管理请求成功返回后才发送确认，而且确认绑定当前管理电脑地址。未在约两分钟内完成确认，会尝试自动恢复。

失败、重启或断电留下的未确认事务也会恢复；开机恢复安排在 fw4 启动之前。关闭时只还原本功能记录的配置项和文件，保留后来新增的账号及其他已提交改动。若其他页面有未应用的修改，恢复会保留记录并提示重试，避免丢弃那些修改。

备份和事务记录位于 `/etc/ocserv/easy-guard`，仅 root 可读；其中可能包含配置中的敏感内容，不要作为诊断附件公开。恢复失败时，页面可再次选择“关闭并恢复”。SSH 恢复命令：

```sh
/usr/bin/lua /usr/libexec/ocserv-easy-guard disable
```

模式开启期间，服务设置页暂时禁止更改 VPN 网络参数。可继续管理账号；需要改地址池、DNS或端口时，先关闭本模式，调整后再开启。

## 适用范围

需要 fw4、dnsmasq、工作中的 ocserv 和已经配置好的 OpenClash（兼容 Clash 与 Meta/Mihomo 内核）。从同一 LAN 的 IPv4 管理地址开启；检测到活跃 WAN 的主路由不应用此旁路由规则。旧配置若把 `ipaddr` 填成地址池中的主机地址，开关会按掩码归一化隔离规则，同时保留原值以便关闭时恢复。若之前部署过旧的手动 `bulijie_guard` 规则，先停用那套规则，避免两套规则同时管理同名对象。

实际 N1/OPL 固件仍需验证端口、DNS、TCP/UDP、OpenClash 模式和重启后的持久化。本功能的隔离网络测试不代表已经连接过用户的 N1。
