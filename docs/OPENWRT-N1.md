# N1 / OpenWrt 25.12 安装

更新日期：2026-10-10。Linkora VPN 服务端：ocserv 1.5.0-r6、管理页 0.5.0-r1。项目只构建 25.12 系列 APK。

## 当前设备

| 项目 | 用户提供的信息 |
|---|---|
| 型号 | Phicomm N1 |
| 架构 | ARMv8 Processor rev 4 |
| 目标平台 | armsr/armv8 |
| 固件 | OPL_FW4 For N1 v0.0.8 |
| LuCI | openwrt-25.12 branch 26.075.80566~6efa8ae |
| 内核 | 6.12.66-flippy-94+ |
| 示例连接地址 | 192.168.19.253:4443（来自最新截图） |
| 拓扑 | 单网口旁路由，普通电脑通过另一台主路由上网 |

官方 SDK 默认自动选择 25.12 系列最新稳定补丁版，N1 软件包架构为 aarch64_generic；OPL 的 APK 工具报告 `aarch64` 也受支持。APK、musl 和各用户态依赖必须匹配实际固件；先使用固件作者配置的软件源。**TUN 来自 OPL/Flippy 自己的内核**：本项目配方不依赖官方 SDK 的 kmod-tun，安装脚本要求现有 `/dev/net/tun` 可用。

## 全新安装：一个脚本

无需先安装其他版本的 ocserv。

1. 下载本次 25.12 服务端 ZIP，核对外部 SHA256SUMS，完整解压。
2. 使用 WinSCP 或 LuCI 文件传输，把解压目录中的文件上传到 N1 的新目录 `/tmp/linkora-vpn`。`install.sh`、两个 APK 和 `SHA256SUMS` 应在同一层；不要混入旧版本的 APK。
3. SSH 登录 N1，以 root 执行：

```sh
cd /tmp/linkora-vpn
sh install.sh
```

脚本会校验套装所有文件、检查固件/架构/TUN、更新现有 APK 软件源索引并预演安装。如果计划安装或更换内核模块则停止。安装前把已有配置备份到 `/root/linkora-vpn-before-install-日期时间-进程号`。

安装的两个包是 `ocserv-1.5.0-r6.apk` 和 `luci-app-ocserv-easy-0.5.0-r1.apk`。安装成功后自动移除重复的原版 LuCI 页面与其翻译包。`--allow-untrusted` 只用于这些自行构建且已经校验的本地 APK；普通依赖仍由固件现有软件源解析，不跳过依赖检查。

全新安装还会生成缺失的 CA/服务端证书、保留私钥文件权限，并配置 ocvpn 区域、VPN 到 LAN 上游的转发、源 NAT 和 4443 入口。它不会开启 OpenClash，也不会修改 OpenClash 配置。端口 4443 和 VPN 网段 10.77.0.0/24 需要与现网错开。

安装或证书步骤失败后可重新运行脚本，继续尚未完成的全新安装。防火墙写入、检查或重载失败时恢复安装前配置；已完成安装后再运行不会重复添加规则。存储报告兼容 OPL 的 btrfs 布局，不再因 `df /etc` 返回错误而中途退出。

## 第一次使用管理页

重新登录 LuCI，打开 **VPN → Linkora VPN**，确认页面显示“管理页 0.5.0”。

1. 在“账号与在线用户”添加账号；新密码至少 8 个字符，输入两次后点击“保存并生效”。程序没有默认账号密码。
2. 在“服务设置”检查端口、VPN 地址池、DNS、每账号在线数和员工连接地址。
3. 点击“启动服务”；需要开机启动时点击“开机自动启动”。
4. 客户端填写 N1 的实际地址和端口，例如 `https://192.168.19.253:4443`，输入账号密码后连接。首次出现证书确认时核对指纹并选择“信息准确，记住并连接”。

需要分发配置时，在管理页“客户端配置”填写客户端可达的地址并下载 `.vpn`；默认包含固定服务器公钥指纹。也可由已连接成功的 Windows 客户端点击“导出配置”，携带已确认的指纹分发。接收者仍需自行填写账号密码。外网、IPv6 和运营商内网部署见[公网连接说明](WAN.md)。

证书由握手自动传给客户端，确认前不会发送账号密码。首次生成的证书包含生成时的 LAN IPv4 地址和路由器主机名。现有证书不会被自动替换；以后换地址、公钥或证书时应核对对应变化。

若菜单没有刷新，先退出并重新登录 LuCI，必要时执行：

```sh
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

## 与 OpenClash 共存

ocserv 负责 VPN 隧道与账号，OpenClash 负责出站代理，两者可以共存。默认服务端安装只准备 VPN 的基本网络转发。OpenClash 必须先完成订阅/节点配置并正常运行。

需要“只有连接 VPN 才能借 N1 使用 OpenClash”时，进入 **VPN 专用上网 → 开启**。开关默认关闭；启用时使用实际 LAN 信息、VPN 地址池及当前管理电脑地址，不要求手工复制 nft 规则。应用可能短暂重启防火墙、dnsmasq、OpenClash 和 ocserv。

成功后页面会自动确认当前管理连接仍可使用；无法确认则在待确认阶段约两分钟后尝试恢复。关闭时恢复本功能改动的设置。详见 [专用上网开关](VPN-ONLY-OPENCLASH.md)。

## 重新安装与排查

Linkora VPN 使用新的应用和防火墙标识，按全新安装部署。先备份当前固件配置，在旧管理页关闭专用上网开关以恢复原网络，再停用旧服务、卸载旧包并清理其 VPN 配置。仅覆盖安装 APK 会保留旧配置，不能替代全新安装。安装新版后重新创建账号、设置网络和客户端连接。

此前跳过安装脚本、仅手动安装 APK 的设备，如果仍使用 `ocvpn`、`10.77.0.0/24` 和 `4443` 默认配置且没有 VPN 防火墙规则，会自动补齐默认转发。已有自定义网络会保留。更新不是固件升级，也不包含旧二进制的自动回滚；请保留原来可用的 APK 和固件备份。

如果改过自定义地址池，需同步检查 VPN 的转发/NAT。启用专用上网开关时会根据当前地址池生成相应规则；关闭时恢复之前的普通网络配置。

新安装不读取旧版密码或专用模式事务备份。请在新版页面重新开启需要的专用上网功能。

如果仍有加载或保存错误，在套装目录运行 `sh diagnose-n1.sh`。它输出组件版本、账号健康计数和管理代码故障位置，不输出用户名、密码、密码哈希或私钥。

## 验收

确认服务版本、TCP/UDP 4443、账号登录、客户端分配的 VPN IP、DNS 与实际网页访问，再测试断开后路由/DNS 恢复。启用专用上网后，再用未连接 VPN 的电脑验证修改网关/DNS或手填 HTTP/SOCKS 端口不能借用 N1。
