# N1 / OpenWrt 25.12 安装

更新日期：2026-10-29。Lansyra 服务端：ocserv 1.6.0-r1、管理页 0.6.4-r1。项目只构建 25.12 系列 APK，从 1.6.0 起按全新安装配置；旧版事务和地址池兼容代码已移除。

## 当前设备

| 项目 | 用户提供的信息 |
|---|---|
| 型号 | Phicomm N1 |
| 架构 | ARMv8 Processor rev 4 |
| 目标平台 | armsr/armv8 |
| 固件 | OPL_FW4 For N1 v0.0.8 |
| LuCI | openwrt-25.12 branch 26.075.80566~6efa8ae |
| 内核 | 6.12.66-flippy-94+ |
| 示例连接地址 | 192.168.19.254:4443（来自最新截图） |
| 拓扑 | 单网口旁路由，普通电脑通过另一台主路由上网 |

官方 SDK 默认自动选择 25.12 系列最新稳定补丁版，N1 这套固件的 `/etc/apk/arch` 为 `aarch64_generic`，应下载 `openwrt-25.12-aarch64_generic`，即使 CPU 型号是 Cortex-A53。`aarch64_cortex-a53` 套装使用 mediatek/filogic SDK，不能仅根据相同 CPU 核心选用。安装器优先读取 `/etc/apk/arch`；OPL 的 APK 工具仅报告 `aarch64` 时，缺少覆盖文件才使用该别名。APK、musl 和各用户态依赖必须匹配实际固件；先使用固件作者配置的软件源。**TUN 来自 OPL/Flippy 自己的内核**：本项目配方不依赖官方 SDK 的 kmod-tun，安装脚本要求现有 `/dev/net/tun` 可用。

## 全新安装：一个脚本

无需先安装其他版本的 ocserv。

1. 下载本次 25.12 服务端 ZIP，核对外部 SHA256SUMS，完整解压。
2. 使用 WinSCP 或 LuCI 文件传输，把解压目录中的文件上传到 N1 的新目录 `/tmp/lansyra`。`install.sh`、两个 APK 和 `SHA256SUMS` 应在同一层；不要混入旧版本的 APK。
3. SSH 登录 N1，以 root 执行：

```sh
cd /tmp/lansyra
sh install.sh
```

脚本会校验套装所有文件、检查固件/架构/TUN、更新现有 APK 软件源索引并预演安装。如果计划安装或更换内核模块则停止。安装前把已有配置备份到 `/root/lansyra-before-install-日期时间-进程号`。

安装的两个包是 `ocserv-1.6.0-r1.apk` 和 `luci-app-ocserv-easy-0.6.4-r1.apk`。如果设备已经安装同名的 Lansyra 包，脚本会使用 APK 原地升级：先备份配置，检测运行状态后暂时停止 ocserv，替换两个包，再恢复原来的运行状态。账号、证书、`/etc/config/ocserv` 和防火墙配置会保留；升级失败会尝试重新启动当前安装的服务，不自动回滚 APK 版本。安装成功后自动移除重复的原版 LuCI 页面与其翻译包。`--allow-untrusted` 只用于这些自行构建且已经校验的本地 APK；普通依赖仍由固件现有软件源解析，不跳过依赖检查。

安装、管理页、后台恢复与套装内 `add-user.sh` 使用同一把进程文件锁；出现“正在执行其他维护操作”时等待当前操作结束后重试，不要删除 `/var/run/ocserv-easy/lock`。专用上网处于待确认或恢复中、普通管理事务待恢复时，安装器会在停止服务前退出；已经确认启用的专用上网可以正常保留升级。`with-lock.lua` 和 `lease.lua` 必须随完整套装上传，首次缺少 Lua/nixio 时脚本会先预演并安装相应运行库。

全新安装还会生成缺失的 CA/服务端证书、保留私钥文件权限，并配置 ocvpn 区域、VPN 到 LAN 上游的转发、源 NAT 和 4443 入口。它不会开启 OpenClash，也不会修改 OpenClash 配置。端口 4443 和 VPN 网段 10.77.0.0/24 需要与现网错开。

ocserv 始终需要 TLS 服务端证书，即使只在公司局域网使用也不能省略。安装脚本会自动生成自签本地 CA、由其签发的服务端证书和对应私钥；证书包含生成时的路由器主机名及 LAN IPv4，不要求域名。局域网客户端建议使用管理页默认的“固定服务器指纹”，这样不必把自签 CA 导入系统信任库。

安装或证书步骤失败后可重新运行脚本，继续尚未完成的全新安装。防火墙写入、检查或重载失败时恢复安装前配置；已完成安装后再运行不会重复添加规则。存储报告兼容 OPL 的 btrfs 布局，不再因 `df /etc` 返回错误而中途退出。

## 第一次使用管理页

重新登录 LuCI，打开 **VPN → 岚序 Lansyra**，确认页面显示“管理页 0.6.4”。

1. 在“账号与在线用户”添加账号；新密码至少 8 个字符，输入两次后点击“保存并生效”。程序没有默认账号密码。
2. 在“服务设置”检查端口、VPN 地址池、DNS、每账号在线数和员工连接地址。
3. 点击“启动服务”；需要开机启动时点击“开机自动启动”。
4. 客户端填写 N1 的实际地址和端口，例如 `https://192.168.19.254:4443`，输入账号密码后连接。首次出现证书确认时核对指纹并选择“信息准确，记住并连接”。

需要分发配置时，在管理页“客户端配置”填写客户端可达的地址并下载 `.vpn`；默认包含固定服务器公钥指纹。也可由已连接成功的 Windows 客户端点击“导出配置”，携带已确认的指纹分发。接收者仍需自行填写账号密码。外网、IPv6 和运营商内网部署见[公网连接说明](WAN.md)。

证书由握手自动传给客户端，确认前不会发送账号密码。现有证书不会被自动替换；以后换地址、公钥或证书时应核对对应变化。若安装时看到 `IPKG_INSTROOT: parameter not set`，请更新到包含初始化脚本修复的套装后重新运行 `install.sh`，该警告会阻止自动证书初始化。

若菜单没有刷新，先退出并重新登录 LuCI，必要时执行：

```sh
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

## 与 OpenClash、Nikki 或 Momo 联动

ocserv 负责 VPN 隧道与账号，所选代理负责出站处理。默认服务端安装只准备 VPN 的基本网络转发。OpenClash、Nikki、Momo 中的一款必须先完成订阅/节点配置并正常运行，不能同时开启多款。

需要“只有连接 VPN 才能借 N1 使用代理”时，进入 **VPN 专用上网 → 开启**。开关默认关闭；启用时使用实际 LAN 信息、VPN 地址池及当前管理电脑地址，不要求手工复制 nft 规则。应用会短暂重启防火墙、所选代理和 ocserv。升级 Nikki/Momo 或切换代理前先关闭本开关。

成功后页面会自动确认当前管理连接仍可使用；无法确认则在待确认阶段约两分钟后尝试恢复。关闭时恢复本功能改动的设置。详见 [专用上网开关](VPN-ONLY-PROXY.md)。

## 重新安装与排查

1.6.0 基线内的同名 Lansyra 更新可重复运行完整套装中的 `install.sh`，不需要先卸载 ocserv；不要手工删除配置或防火墙规则。1.5 及更早版本不属于本版升级范围：先在旧管理页关闭专用上网开关、备份配置、停用并卸载旧包，再按全新安装部署。旧账号、证书和事务不会自动迁移。

完整套装通过 `install.sh` 完成首次网络设置；同名升级只更新包文件并保留现有配置，不重复添加防火墙规则。不要只复制 APK 文件或混入旧 APK；必须使用同一套装中的 `install.sh`，这样才能获得校验、备份、证书和服务状态恢复。

管理页修改地址池、TCP 或 UDP 端口时会同步更新项目维护的基础防火墙规则，并在 fw4 检查和重载失败时自动恢复。启用专用上网开关时会根据当前地址池生成隔离规则；关闭时恢复之前的普通网络配置。

本版不提供旧版密码或专用模式事务的自动迁移。请在新版页面重新开启需要的专用上网功能。

如果仍有加载、保存或 VPN 外网访问错误，在套装目录运行 `sh diagnose-n1.sh`。它输出组件版本、账号健康计数、管理代码故障位置，以及 VPN DNS/路由、代理入口、实际透明代理端口、TCP/UDP 监听和 IPv4 TUN 路由状态。端口来自生成的 nft 规则，手动修改后诊断随运行规则更新；`mixed-port` 不能替代透明代理入口。监听存在仅表示内核中有对应端口，仍需检查代理日志与实际流量。诊断不输出用户名、密码、密码哈希、订阅或私钥。

## 验收

确认服务版本、TCP/UDP 4443、账号登录、客户端分配的 VPN IP、DNS 与实际网页访问，再测试断开后路由/DNS 恢复。启用专用上网后，再用未连接 VPN 的电脑验证修改网关/DNS或手填 HTTP/SOCKS 端口不能借用 N1。

本地构建和隔离测试已经覆盖相关代码路径；此项目尚未在用户这台 OPL v0.0.8 / Flippy 内核上完成真实转发验收。
