# 客户端配置与分发

## 用服务端已有的 ca.pem

服务端 LuCI 中“查看该服务器使用的 CA 证书”的功能可以直接使用。保存完整的 `-----BEGIN CERTIFICATE-----` 至 `-----END CERTIFICATE-----` 内容为 `ca.pem`，通过公司认可的渠道发给员工。

员工填写服务器地址，点击“导入配置”，在文件类型里选择“CA 证书”，选中 `ca.pem` 即可。程序验证它是有效的 CA 证书，将其放在当前用户的应用目录，并且只对本 VPN 连接生效。程序不会修改 Windows 全局根证书库，也不会自动信任连接时从未知服务器取得的证书。

CA 受信任不代表任何服务器名称都有效。现有 OpenWrt 自动签发的服务器证书可能只有 `OPLForN1` 主机名；若客户端使用 `192.168.19.254`，服务器证书应包含 `IP:192.168.19.254` 的 SAN。否则应使用证书内的域名并正确解析，或由管理员重新签发服务器证书。不能通过关闭名称校验解决。

## 更简单的一次导入

在 N1 上运行随源码提供的导出脚本：

```sh
sh export-profile.sh https://192.168.19.254:4443 /etc/ocserv/ca.pem /tmp/company-vpn.bvpn
```

将生成的 `company-vpn.bvpn` 发给员工，员工点一次“导入配置”即可同时设置服务器与 CA。这个文件仅含服务器地址和公共 CA，不含账号密码、服务器私钥或 CA 私钥。导入后锁定服务器文本框；换服务器通过导入新配置完成。

文件格式是 INI：

```ini
[VPN]
Server=https://192.168.19.254:4443
CABase64=此处为ca.pem文件字节的完整Base64
```

`CABase64` 可以编码 PEM 或 DER 的单个 CA 证书。需要公钥固定模式时，可以用 `ServerPin=pin-sha256:...` 替代 `CABase64`，两者不能同时出现。导入会拒绝私钥、过期 CA、无信任材料及非 HTTPS 地址。

## 密码保存

勾选“记住账号和密码”并点击连接时，程序调用 Windows Credential Manager，使用当前 Windows 用户的本机持久凭据存储。配置 INI 只保存普通首选项和账号名，不包含密码。凭据目标是服务器 URL、CA 内容或固定公钥的 SHA-256 标识。

更改地址或信任配置会使用不同凭据记录，因此不会把旧密码自动填给新的服务器。用户修改账号时会清除原来自动填入的密码。取消勾选会删除当前连接的已存凭据；其他历史连接的记录可以在 Windows“凭据管理器 → Windows 凭据 → 普通凭据”中管理，名称以 `BulijieVPN/` 开头。

UAC 使用同一个 Windows 用户提升权限时可以读取该用户的已存凭据。若标准用户通过另一管理员账号启动，则属于另一个 Windows 用户，不能读取原用户的凭据。未勾选记住时，提升到新进程后需重新输入密码，或一开始就以管理员身份运行。

## 文件与优先级

- `布利杰VPN.exe`：主程序。
- `wintun.dll`：对应架构的官方驱动组件，必须同目录。
- `BridgeVPN.ini`：管理员提供的初始配置；没有导入配置时使用。
- `%LOCALAPPDATA%\BridgeVPN\connection.ini`：用户导入的连接配置，优先于初始配置。
- `%LOCALAPPDATA%\BridgeVPN\ca-<hash>.pem`：该连接的私有信任 CA。
- `%LOCALAPPDATA%\BridgeVPN\settings.ini`：语言、账号名、记住选项等。

高级配置在初始 `BridgeVPN.ini` 中包括 `ServerPin`、`CAFile`、`AuthGroup`、`PreferUDP`、`ReconnectSeconds`、`ProtectDNS`、`BlockUntunneledIPv6`。导入文件采用常用安全默认值，当前面向 ocserv 的单组账号密码认证，不提供 SSO、验证码、设备证书或任意脚本执行。

## 连接、托盘与退出

- 空账号或空密码会提示错误，不启动网络连接或 UAC 提升。
- 连接过程中可取消；连接成功后可断开。
- 最小化后窗口隐藏到通知区域；如果 Windows 自动折叠图标，可在右下角小箭头内找到。
- 单击图标还原窗口；右键菜单可显示窗口、断开/取消或退出。
- 关闭窗口即退出，并先取消连接和清理网络，不是仅隐藏窗口。
- 如果 Explorer 重启，程序会尝试重建托盘图标。

## Win7 部署

使用 Win7 SP1、匹配架构的发行包，安装所需的系统安全更新，特别是 SHA-2 签名支持（KB4474419 及对应服务堆栈更新 KB4490628）和安全 DLL 加载支持（KB2533623 或其替代更新）。这些是操作系统更新，并非本程序的额外语言运行环境。当前尚没有 Win7 实机验收结果。
