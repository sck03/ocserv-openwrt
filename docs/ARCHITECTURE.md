# 模块边界与维护约定

## 运行模块

| 模块 | 负责内容 | 边界 |
|---|---|---|
| Windows `application`、`ui`、`dialogs` | 界面、交互、托盘、事件消费；偏好保存后台合并；网络通知去重 | 不从 UI 线程访问活动的 OpenConnect 对象；偏好保存结果通过窗口消息回传 |
| Windows `session`、`certificates` | 工作线程、认证、证书、命令管道和资源回收 | 会话 ID、状态代次及取消控制隔离晚回调；核心只由工作线程释放 |
| Windows `profile`、`platform` | 数据格式、加密、大小限制、原子写入、受管 CA 清理 | 保存前检查与读取相同的整体上限；非凭据更新保留不透明密文 |
| Windows `preferences_writer` | 有界单槽的偏好保存、去抖和退出刷新 | 后台串行写入最新状态；完成结果留在模块内部，窗口消息只负责唤醒 |
| Windows `network_policy` | 全隧道识别和动态 IPv6 防绕行策略 | 策略随会话或进程结束移除；不写永久防火墙规则 |
| Linux `main`、`agent`、`protocol` | GTK 交互、认证助手 IPC、纯校验和代次 | 系统权限、隧道、DNS 和路由归 NetworkManager 管理 |
| Linux `helper_process` | 认证助手异步收尾、超时终止与进程回收 | 收尾命令、管道关闭和等待退出均不阻塞主循环；所有异步操作结束后释放请求归属 |
| Apple 应用与 `client/apple` | 应用配置/钥匙串、扩展生命周期、数据包通道 | 密码仅随启动选项传递；核心回调绑定代次，停止屏障等待网络设置实际完成 |
| Apple `NetworkSettingsOperation` | 网络设置完成状态、错误与异步屏障 | 调用超时或停止不提前释放屏障；新连接须等待旧系统设置回调 |
| macOS `ProfilePersistence` | JSON 大小预算、原子替换和凭据更新恢复 | 编码预算先于钥匙串修改；文件替换失败恢复旧凭据 |
| Android `SessionOwner` | 进程内唯一的启动/工作线程归属 | 超时通知不释放仍在执行的工作线程；完成回调校验身份与代次 |
| Android `SessionControl`、`PromptWait` | 原生会话发布、异步命令、释放及可取消的认证等待 | 取消早于会话或弹窗发布仍有效；异步调用不能使用已释放核心 |
| Android `NetworkRoutes`、`RoutePolicy` | 数字网络规则选择和双栈路由补集 | 归并区间后顺序扫描；输入分别最多 4096 条，最终输出最多 2048 条 |
| Android `ProfilePolicy`、`ProfileCodec` | 配置校验、来源绑定、格式和加解密失败处理 | 不依赖 Android 存储；DataStore 只负责事务持久化 |
| Android `DiagnosticLog` | 已知秘密、认证结构和 URL 过滤 | 清理后才发布到界面或 Logcat；日志历史另有数量与字符预算 |
| 服务端 `logic`、`firewall` | 纯校验、配置渲染、受管防火墙定义 | 无进程或文件系统副作用，可直接做 Lua 回归 |
| 服务端 `backend`、`guard` | 一致的配置快照、普通配置事务、可恢复的 VPN-only 事务 | 快照读取前后核对文件；写入受互斥锁、修订、待提交变更和权限检查约束 |
| 服务端 `guard_state` | 隔离恢复记录的纯结构校验与受管目标定义 | 不访问文件或启动命令；复用代理登记表，在状态展示、确认、应用和恢复前统一检查 |
| 服务端 `proxy_registry`、`proxy` | 代理身份/能力登记、服务归属、配置计划和入口就绪检查 | 三款已验证适配共用事务；其他已知服务仅检测和提示。核心进程名不能代替软件适配；不新增常驻轮询 |
| 服务端 `storage`、`configuration` | 有界原子文件 IO、流式行扫描、候选作用域和持久恢复记录 | 文件读取与扫描共用打开错误处理；扫描独立于代理策略。`with_stage` 管理原生 UCI 候选从创建到清理的完整生命周期；恢复前检查全部文件，后续修改保留现场 |
| 服务端 `process`、`guard_log` | 有时限的子进程执行、结构化日志 | 不经过 shell 拼接；区分 EAGAIN/EINTR 与真实 I/O 错误，所有失败路径回收进程；日志不保存原始命令输出和凭据，并复用有界原子存储 |
| 服务端 `lease`、安装工具 `with-lock` | LuCI、恢复和 shell 维护共用 POSIX 租约 | 锁文件不删除；同 PID exec 保留所有权，进程退出自动释放；不用不兼容的 flock 替代 |
| 服务端 `query_cache` | 可丢弃的在线/版本/能力快照 | 完成查询后开始有效期；独立失效代次隔离跨进程迟到写入；命中时无写入或子进程，配置事务不依赖缓存正确性 |
| 服务端 `occtl`、`json_array` | 会话查询策略、增量对象分帧和显示字段裁剪 | `json_array` 只管理数组边界、字符串转义和记录预算，由 jsonc 解码每条对象；`occtl` 检查会话字段。复用进程流式输出，失败不发布部分结果 |
| 管理页 `app.js` | 页面状态、编辑、请求与局部渲染 | `readSlot` 统一只读请求的去重、取消及完成归属；页面决定失效时机。提交与结果刷新共用忙碌周期；页面拥有列表视图状态、权限与操作 |
| 管理页 `table.js` | 搜索、分页、计数与可见行更新 | 每页最多创建 50 行，仅序列化可见数据比较；没有请求、定时器或后端状态依赖，行渲染和文案由页面传入；外部视图状态仅保存搜索文字与页码 |

## 生成代码与上游更新

原生依赖的下载校验与编译选择共用锁定清单：Windows 使用 `scripts/sources.json`，Android / Apple 使用 `mobile/sources.json`。`build_common.source_directory` 与 `source-directory.py` 统一解析目录及版本，移动端同时核对归档名与目录名；Android 参数、Apple 配置及头文件复制不再维护独立的版本常量。解析工具随对应源码包提供。共享的 OpenConnect、libxml2 归档由回归检查跨平台 SHA-256 一致性。

Android 上游保持 `mobile/sources.json` 中的固定提交和 SHA-256，不直接修改下载缓存。`prepare-mobile-android.py` 处理构建、标识和网络适配，`android_maintenance.py` 处理生命周期、存储和诊断；两者通过 `source_edits.py` 对固定源进行精确编辑。每个匹配必须唯一，输入发生变化即停止构建。纯策略源码和对应 JUnit 位于 `mobile/android/`，随适配复制到生成工程。

Windows 协议修改保持为独立 OpenConnect 补丁。下载源码不变，补丁只作用于构建目录，零模糊应用。新增脚本取消补丁仍允许断开清理脚本执行，不能为了响应取消而跳过路由回收。

新增模块时同时检查对应源码打包清单、包内审计、工作流和测试入口。源代码清单读取当前 Git 跟踪文件，未跟踪的新文件不会自动进入对应源码包。

## 数据和恢复契约

- Windows：schema 2，整体不超过 8 MiB；DPAPI 绑定配置 ID、当前用户和服务器来源。保存失败保留原文件。
- Windows 界面只加载不透明凭据；连接工作线程解密当前配置。CA 安装、配置保存与孤立证书清理共用一个租约。
- macOS：schema 1，最多 128 项且序列化整体不超过 1 MiB；数据与钥匙串保持失败恢复关系。
- Android：最多 128 个配置，持久化 JSON 不超过 1 MiB；加解密或解析失败不转为空存储。延迟的指纹更新同时检查配置 ID 与来源。
- 同一来源的认证路径变化可以保留绑定；服务器主机或端口变化需要清除原凭据与信任。其他产品的历史数据不隐式迁移。
- 普通服务设置同时提交 ocserv 与受管防火墙。项目拥有四个命名段的完整定义，其他管理员规则不属于该模块。
- `backend.snapshot` 在创建 UCI 游标前读取原始 ocserv / firewall 文件，全部字段读取后再次按内容核对；并发变更返回 `stale_revision`，I/O 错误保持原错误，不带着不一致数据继续查询或修改。读取不新增锁、临时文件或自动重试；与配置写入共用原有快照入口。`logic.revision` 依次消费原始文件与分隔符，避免拼接最多约 1 MiB 的中间字符串。校验后发生的写入仍由提交时的修订和事务检查处理。
- 请求入口、普通/隔离恢复记录和 occtl 会话响应在 jsonc 解码前复用 `logic.json_has_null` 拒绝字符串外的 `null`，避免显式字段或数组末尾被直接丢弃。当前数据契约不包含 nullable 字段；恢复记录以 `false` 表示原值不存在，省略可选字段仍遵循各自定义。扫描通过字符串查找跳过正文，正确处理引号与转义，不复制整个快照；解码后的结构校验仍保留。异常恢复记录在写入或服务操作前失败，在线查询报错，无法确认会话撤销时回滚账号事务。
- `logic.validate_settings` 在任何写入前复用 `logic.array` 检查 DNS（1–3 项）及分流路由（1–128 项）的完整结构；路由在输入预算内按数字地址与前缀去重，保持首次出现顺序。校验和归一化不依赖 UCI，后台事务仅消费完整结果；重复路由不触发无效配置提交或重启。
- 普通服务事务使用固定目录 `/etc/ocserv/easy-transaction`，候选文件各不超过 256 KiB；后台、下次修改和启动均可恢复未完成的文件替换。服务恢复成功后才清除事务状态。
- `configuration.with_stage` 在共享租约内创建、校验、加载并清理固定 UCI 候选及 delta 文件。普通保存与代理接入均在此作用域内执行，包括恢复记录创建和事务收尾；后台不再提前准备代理候选，也不为恢复回滚临时游标。持久恢复只使用 journal 和原始快照，候选清理不会删除它们。预检另用受保护的作用域清理 `check.conf` 和 `check.passwd`；进程被强制终止时不保证执行清理，固定临时路径可被后续操作覆盖，重启清空 `/var/run`。
- 普通恢复清单必须是连续数组，最多 7 个唯一目标；完整检查后才恢复文件。恢复计划只保留待写回的原始内容，已恢复文件不进入计划，也不保留当前候选内容；重复恢复不增加文件写入。
- 隔离记录为 schema 3，`started` 始终为布尔值。`guard_state` 校验清单、UCI 值、配置快照、固定文件目标和状态展示字段；坏记录在配置写入或服务命令前被拒绝，状态显示恢复异常。旧格式不迁移，升级前须用原版本关闭隔离并完成恢复。
- `storage.read` 只在 ENOENT 时返回 `nil`，存在的空文件返回空字符串，其他打开或读取错误抛出 `read_failed`。隔离状态读取采用同一实现，预算为 2 MiB；空白状态必须通过解析拒绝，不能视为未开启。原子写入通过 nixio 的零起始偏移重试部分写入，复用原字符串。
- `storage.scan_lines` 按最多 4 KiB 分块扫描，单行最多 4 KiB，支持跨块行和无换行的末行；调用方指定总字节预算，回调返回 `false` 可提前结束。不存在返回 `nil`，读取、预算或回调错误向上传递，结束及异常均关闭句柄。`proxy` 每次先收集规则目标，再统一扫描 TCP/UDP 的 IPv4/IPv6 表，每张表最多 4 MiB；只保存目标端口，全部找到后跳过余下内容及同协议的下一张表。没有目标则不读取连接表。已观测端口为真，只有两张表都完成扫描才能判定未发现端口为假，其他情况为未知；检测不新增缓存或常驻任务。
- 安装器首次网络初始化保存候选和原始配置；VPN-only 事务另有状态、确认和恢复记录。检测到后续修改时保留现场，不用旧快照覆盖。
- 后台偏好写入、系统网络设置等待和查询缓存各自封装为单一模块；UI/控制器负责组合，模块不依赖具体窗口或页面。新增字段、平台策略和恢复职责应沿这些边界扩展，避免复制生命周期逻辑。
- Linux 收到完整认证结果后异步发送 `QUIT`，最多等待 1 秒，超时或写入失败终止助手；失败及取消直接终止。进程退出和管道操作完成后才回调并释放请求，期间新请求仍受单槽约束。收尾期间取消仍拒绝返回凭据，助手提前退出会取消未完成的写入；计时器只在收尾时存在，不限制用户填写认证表单的时间。
- 查询缓存每个名称使用固定的 JSON 快照和 32 字节随机代次标记。刷新及显式失效先原子替换标记；查询只发布自己的代次，读取快照后再核对标记。旧查询即使在失效后的重命名窗口写入，也不会被后续请求接受。无需持有配置租约或等待其他查询；失败时返回实时结果，标记和快照均可丢弃，不迁移旧缓存格式。
- 页面同时跟踪请求期间的新编辑和请求开始前已有的未保存表单。后台完整刷新与隔离确认在表单结束后执行，合并多次状态变化；等待期间不更新表单修订号，避免用新修订号提交旧字段而绕过冲突检查。成功保存和显式刷新清除延后刷新状态。
- 每个只读查询槽最多保留一个请求及控制器。取消先释放归属再中止 fetch，新请求可立即开始；旧成功、异常和 finally 均检查归属，不能发布或清空新请求。完整刷新、状态轮询和只读弹窗复用同一实现，配置提交保留独立的超时与结果处理。
- 账号与在线列表先筛选并截取当前页，再调用行工厂，不为其他页创建节点或事件闭包。其他页数据变化不重建当前行；计数、分页按钮及状态通知仅在值变化时更新。完整刷新重新创建列表以重新应用权限，保留搜索与有效页码；切换标签释放旧列表引用。新模块随 LuCI 资源打包，JavaScript 与 CSS 禁用 SDK 改写并逐文件核对安装包摘要。
- 账号在线状态由 `app.js` 按完整登录名称、区分大小写汇总当前在线快照；UCI 账号 ID 与 occtl 会话 ID 各有用途，不互相匹配。每次更新只扫描一次会话并就地更新至多 50 个账号标记，无额外请求、定时器或行重建。查询或 HTTP 轮询失败时标记未知并隐藏旧连接操作；被取消或过期的请求不改变状态。
- 普通命令仍捕获最多 128 KiB 输出。`process.run` 的可选流式消费者允许显式指定总字节预算，不累计输出；消费者拒绝或抛错复用进程组终止和回收路径。`occtl` 每次最多消费 64 MiB、每条最多 64 KiB、嵌套最多 32 层；在线最多 4096 条，缓存会话最多 65536 条，分别限时 4 秒和 5 秒。只保留裁剪后的在线字段，撤销核实不保留条目。完整数组结束及命令成功后才发布；发现目标仍有会话时提前终止核实并返回失败。缓存文件继续使用原 256 KiB 上限，超限结果仍可实时显示。
- `process.run` 分别跟踪主进程回收与输出 EOF，两者都完成才返回退出码；EAGAIN 仅表示暂时无数据。主进程已回收时不再调用 waitpid，后代持有的管道仍受原时限及预算约束，失败只终止剩余进程组。`occtl` 的显示裁剪在 UTF-8 边界回退，保持 64/128 字节预算；短字段直接复用，长字段只检查截断处，不遍历全文。IPv4 经过字段归一化后为空时才选用 IPv6。
- 服务端打包按当前源码清单自动核对所有 Lua 运行模块的摘要，删除手工重复的模块名称列表；新增模块随源码包分发并自动进入安装包审计。

## 验证与清理

先运行与修改相关的纯逻辑和边界回归，再运行目标平台编译、原生认证/脚本/窗口回归及包审计。服务端安装恢复测试包含提交后和收尾前的进程中断；浏览器测试包含挂起、重复请求和无变化轮询。`tests/lua_json.py` 为 JSON 边界用例提供实际文本编码/解码，并模拟 jsonc 的 null→nil 转换；其他 OpenWrt 接口仍由隔离测试夹具模拟。

Apple unsigned 构建、Android JUnit、NetworkManager IPC 和模拟 UCI 均不能替代真实设备的签名授权、转发、睡眠、网络切换及长期测试。构建证据和设备证据分别记录在 `VALIDATION.md`，不把编译成功写成连接成功。

使用 `scripts/clean-workspace.ps1` 先预览再清理生成物。默认保留发行包、安装前备份、验证证据、锁定源码归档及许可证；`-DeepClean` 还会删除工具链、依赖和旧验证缓存，下次构建需重新下载。私有配置和发行包始终保留，仍需保存的验证摘要先归档到清理范围之外。自动导入 CA 的清理只在配置保存/删除成功后执行，不删除外部或手动命名的证书。

平台策略优先放在可独立验证的模块，界面只组合策略和平台调用。新增模块必须进入对应源码包与安装包审计；故障回归应覆盖对外行为，不能仅断言适配脚本包含某段文本。更改生成工程应修改固定上游的适配配方，不提交构建缓存。
