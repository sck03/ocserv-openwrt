# 模块边界与维护约定

## 运行模块

公共 `.vpn` 与管理接口的字段、版本和平台能力见 [CONNECTION-PROFILE.md](CONNECTION-PROFILE.md)。公共连接信息与平台私有设置分离，新增字段先定义支持范围，再接通校验、持久化、执行和界面。

当前版本使用管理接口 v3、设置契约 3、隔离记录 schema 4 和可丢弃查询缓存格式 2。公共 `.vpn` 仍为版本 1；Windows schema 3、Android schema 4、macOS schema 2 的文件结构未改变，不新增旧版本迁移层。管理端统一下发隧道 DNS，代理端负责后续 DNS/代理分流。

主要职责边界：

- `client/system_proxy` 单独处理系统代理与绕过匹配；`client/connection_file.h` 同时供 Windows、Linux 的公共文件解析使用。
- Linux `profile_settings` 负责克隆原连接、导入及受管 CA，保留界面未管理的 NetworkManager 字段。
- Apple `RouteSettings` 负责双栈路由与 DNS，`apple-app/ConnectionFile` 供 iOS/macOS 共用，不持有会话状态。
- Android `HotpCounter` 在生成验证码前预留下次计数；`SpeedHistory` 管理有界、带会话归属的时间序列，`MainPagerScreen` 在图表页面订阅快照。
- Android `Strings` 集中维护中文、英文和波斯文；配置选择保存在配置所属 DataStore，与删除在同一事务提交。
- 服务端 `logic.validate_dns` 管理地址族及入口冲突规则。`client_profile` 负责目标能力、不可用原因和公共文件编码，后端在保存和下载时读取所选信任材料。LuCI 根据快照渲染按钮和错误原因。`package_version` 缓存安装包元数据。
- 服务端导出与 Windows、Linux、Apple、Android 导入测试共用 `client/tests/public-profiles`。样例覆盖固定指纹、首次确认和冲突的信任字段。新增证书方式时应同步更新平台能力与导入测试。

| 模块 | 负责内容 | 边界 |
|---|---|---|
| Windows `application`、`ui`、`dialogs` | 界面、配置编辑、托盘、偏好与系统通知 | 消费值快照，不直接访问活动的 OpenConnect 对象 |
| Windows `connection_controller` | Session、事件队列及代次游标；启动、取消和终态回收 | 过滤晚回调，禁止事件消费重入，收回工作线程后释放窗口资源 |
| Windows `session`、`session_auth`、`certificates` | 工作线程、独立认证回调、证书、命令管道和资源回收 | 会话 ID、状态代次及取消控制隔离晚回调；核心只由工作线程释放 |
| Windows `profile`、`platform` | 数据格式、加密、大小限制、原子写入、受管 CA 清理 | 保存前检查与读取相同的整体上限；非凭据更新保留不透明密文 |
| Windows `preferences`、`preferences_writer` | 独立小文件、有界单槽的偏好保存、去抖和退出刷新 | 不扫描配置列表、不解密凭据；后台串行写入最新状态，窗口消息只负责唤醒 |
| Windows `storage_operation` | 用户发起的配置读写与退出刷新 | 每次只执行一个后台操作；模态窗口继续处理消息，不允许重入提交；关闭前收回工作线程，不使用 detached 线程 |
| Windows `route_coverage`、`network_policy` | 归并数字 IPv4 区间识别完整覆盖；动态 IPv6 防绕行策略 | 支持多段及重叠的等价全隧道；策略随会话或进程结束移除 |
| Windows `hotp_counter`、`ProfileStore.reserve_hotp` | 计数校验、来源绑定和原子预留 | 生成验证码前核对当前令牌并保存下一计数；失败终止认证，不依赖上游解锁回调返回值 |
| Linux `main`、`profile_editor` | GTK 展示、配置草稿与操作结果 | 编辑器不写 NetworkManager，成功提交后才清理受管 CA |
| Linux `connection_controller`、`agent`、`protocol` | 连接归属、重试、取消、认证助手 IPC 和纯校验 | 控制器不持有 GTK 控件；系统权限、隧道、DNS 和路由归 NetworkManager |
| Linux `helper_process` | 认证助手异步收尾、超时终止与进程回收 | 收尾命令、管道关闭和等待退出均不阻塞主循环；所有异步操作结束后释放请求归属 |
| Linux `preferences` | 偏好与自动启动文件的后台串行持久化 | GTask 执行磁盘操作；合并排队快照，所有完成回调在主循环执行；退出等待完成 |
| Apple 应用与 `client/apple` | 应用配置/钥匙串、扩展生命周期、数据包通道 | 密码仅随启动选项传递；核心回调绑定代次，停止屏障等待网络设置实际完成 |
| Apple `NetworkSettingsOperation` | 网络设置完成状态、错误与异步屏障 | 调用超时或停止不提前释放屏障；新连接须等待旧系统设置回调 |
| macOS `ProfilePersistence` | JSON 大小预算、原子替换和不可变凭据版本 | 新建钥匙串项、提交配置引用、回收旧项；中断只留下未引用项，不修改旧文件引用的密码 |
| macOS `ProfileRepository` actor | 文件、导入与 Keychain 串行访问 | 接受值快照，不访问界面或隧道；主线程只更新结果，异步恢复和连接按代次拒绝过期完成 |
| Android `SessionOwner` | 进程内唯一的启动/工作线程归属 | 超时通知不释放仍在执行的工作线程；完成回调校验身份与代次 |
| Android `SessionControl`、`PromptWait` | 原生会话发布、异步命令、释放及可取消的认证等待 | 取消早于会话或弹窗发布仍有效；异步调用不能使用已释放核心 |
| Android `NetworkRoutes`、`RoutePolicy` | 数字网络规则选择和双栈路由补集 | 归并区间后顺序扫描；输入分别最多 4096 条，最终输出最多 2048 条 |
| Android `ProfilePolicy`、`ProfileCodec`、`ProfileProjection` | 配置校验、编辑意图、来源绑定及共享元数据投影 | 相同 JSON 只解码一次，选择变化不解密；新输入与继承旧值分开处理 |
| Android `UpstreamMonitor`、`UpstreamPolicy` | 最佳物理网络及地址变化、旧系统选择策略 | 回调串行且绑定生命周期，150 ms 合并事件；不采用最后一次可用网络回调 |
| Android `StatisticsSampler`、`StatisticsPolicy` | 页面、通知、小组件和屏幕状态决定采样需求 | 无需求就无统计定时器；唤醒锁使用独立续期任务 |
| Android `DiagnosticLog` | 已知秘密、认证结构和 URL 过滤 | 清理后才发布到界面或 Logcat；日志历史另有数量与字符预算 |
| 服务端 `logic`、`firewall` | 纯校验、配置渲染、受管防火墙定义 | 无进程或文件系统副作用，可直接做 Lua 回归 |
| ocserv 包 `ocserv.logic/storage/process/runtime` | 服务和管理页共用的渲染、存储、进程与预检 | 安装到 `/usr/lib/lua/ocserv`，不依赖 LuCI 页面；原生 UCI 读取使用 `foreach`，不调用 LuCI 扩展方法。init 只管理证书和进程；安装器实际执行同一渲染预检。当前产品使用 plain 认证和独立地址池，不提供代理 ARP 自动修改 LAN 的旧路径 |
| 服务端 `backend`、`guard` | 一致的配置快照、普通配置事务、可恢复的 VPN-only 事务 | 快照读取前后核对文件；写入受互斥锁、修订、待提交变更和权限检查约束 |
| 服务端 `guard_state` | 隔离恢复记录的纯结构校验与受管目标定义 | 不访问文件或启动命令；复用代理登记表，在状态展示、确认、应用和恢复前统一检查 |
| 服务端 `proxy_registry`、`proxy` | 代理身份/能力登记、服务归属、配置计划和入口就绪检查 | 三款已验证适配共用事务；其他已知服务仅检测和提示。核心进程名不能代替软件适配；不新增常驻轮询 |
| 服务端 `storage`、`configuration` | 有界原子文件 IO、流式行扫描、候选作用域和持久恢复记录 | 文件读取与扫描共用打开错误处理；扫描独立于代理策略。`with_stage` 管理原生 UCI 候选从创建到清理的完整生命周期；恢复前检查全部文件，后续修改保留现场 |
| 服务端 `process`、`guard_log` | 有时限的子进程执行、结构化日志 | 不经过 shell 拼接；`nixio.exec` 使用 execv，调用方必须提供可执行路径，不搜索 PATH。区分 EAGAIN/EINTR 与真实 I/O 错误，所有失败路径回收进程；日志不保存原始命令输出和凭据，并复用有界原子存储 |
| 服务端 `lease`、安装工具 `with-lock` | LuCI、恢复和 shell 维护共用 POSIX 租约 | 锁文件不删除；同 PID exec 保留所有权，进程退出自动释放；不用不兼容的 flock 替代 |
| 服务端 `query_cache` | 可丢弃的在线/版本/能力快照 | 完成查询后开始有效期；独立失效代次隔离跨进程迟到写入；命中时无写入或子进程，配置事务不依赖缓存正确性 |
| 服务端 `certificate_material` | 实际服务端证书选择、Pin 与 CA 验证 | 验证 CA 链和导出地址，复读检测材料变化；界面只消费可用性及错误原因 |
| 服务端 `occtl`、`json_array` | 会话查询策略、增量对象分帧和显示字段裁剪 | `json_array` 只管理数组边界、字符串转义和记录预算，由 jsonc 解码每条对象；`occtl` 检查会话字段。复用进程流式输出，失败不发布部分结果 |
| 管理页 `app.js` | 页面状态、编辑与局部渲染 | 页面决定请求失效时机；提交与结果刷新共用忙碌周期；页面拥有列表视图状态、权限与操作 |
| 管理页 `api.js`、`messages.js`、`dom.js` | 请求生命周期、文案与 DOM 工厂 | API 通过参数接收入口/token；`readSlot` 统一去重、取消及完成归属；文案和 DOM 模块不持有页面状态 |
| 管理页 `table.js` | 搜索、分页、计数与可见行更新 | 按页面注入的唯一键复用行，仅保留最多 50 个当前页节点及逐行比较数据；没有请求、定时器或后端状态依赖，行渲染和文案由页面传入；外部视图状态仅保存搜索文字与页码 |
| 管理页 `maintenance.js` | 卸载步骤和剪贴板交互 | 无请求、定时器或后台权限；DOM 工厂和翻译由页面注入，SSH 执行卸载 |
| 管理页 `accounts.js`、`settings.js`、`guard.js`、`export.js` | 账号表单、服务设置、隔离诊断和配置导出 | 显式注入交互能力；渲染接收状态快照和目标容器，不持有全局页面状态 |
| 服务端 `lansyra-uninstall`、`run.lua`、`network.lua` | 停服、备份、规则清理、包删除和中断恢复 | 套装与安装后命令共用源码和 `with-lock` 租约；`run.lua` 复用有时限的进程执行器，不依赖系统 `timeout`；`network.lua` 读取公共防火墙定义，安装、管理和卸载共用规则清单。卸载全程保留 Lua/nixio，独立执行副本和恢复资料不随 APK 删除 |

## 生成代码与上游更新

原生依赖的下载校验与编译选择共用锁定清单：Windows 使用 `scripts/sources.json`，Android / Apple 使用 `mobile/sources.json`。`build_common.source_directory` 与 `source-directory.py` 统一解析目录及版本，移动端同时核对归档名与目录名；Android 参数、Apple 配置及头文件复制不再维护独立的版本常量。解析工具随对应源码包提供。共享的 OpenConnect、libxml2 归档由回归检查跨平台 SHA-256 一致性。

Android 上游保持 `mobile/sources.json` 中的固定提交和 SHA-256，不直接修改下载缓存。连接、服务、仓库、模型、交互总线、界面适配与加密逻辑直接维护在 `mobile/android/owned/`；纯策略与 JUnit 位于 `mobile/android/`。`prepare-mobile-android.py` 仅负责构建/标识适配和源码复制，已删除 `android_maintenance.py` 及业务字符串替换。设置展示允许错误占位，但连接从严格的 DataStore 读取一次设置快照，并按该快照选择、解密配置；读错、坏枚举或失效选择均不能回退后连接。

Windows 协议修改保持为独立 OpenConnect 补丁。下载源码不变，补丁只作用于构建目录，零模糊应用。新增脚本取消补丁仍允许断开清理脚本执行，不能为了响应取消而跳过路由回收。

新增模块时同时检查对应源码打包清单、包内审计、工作流和测试入口。源代码清单读取当前 Git 跟踪文件，未跟踪的新文件不会自动进入对应源码包。

## 数据和恢复契约

- Windows：`profiles.json` schema 3，整体不超过 8 MiB；`preferences.json` schema 1，上限 16 KiB。偏好写入不读取配置；组合读取时校正已删除的选择/自动连接引用。DPAPI 绑定配置 ID、当前用户和服务器来源。失败保留对应原文件。
- Windows 界面只加载不透明凭据；连接工作线程解密当前配置。CA 安装、配置保存与孤立证书清理共用一个租约。`ProfileEdits` 为非持久化输入意图，服务器变化仅清除继承值；验证和保存共用同一策略，保存失败不改写调用方草稿。HOTP 只解密所选令牌，以期望值比较后原子预留下一计数。
- macOS：schema 2，最多 128 项且整体不超过 1 MiB；钥匙串账户绑定配置 ID、来源和随机版本引用。同一来源、相同密码复用引用，配置不变时不写文件；密码或来源变化才创建新版本。替换失败清理新项，提交成功后才清理旧项；进程中断可能留下孤立钥匙串项，避免不安全的全局扫描清理。
- Android：schema 4，最多 128 个配置，JSON 不超过 1 MiB。AES-GCM AAD 绑定 ID、来源与凭据种类，列表不解密。`ProfileEdit` 显式标记本次输入；来源变化清除继承凭据/信任，保留新输入。相同来源的空密码/令牌仍保留原值，关闭相应开关可清除。`ProfileProjection` 共用一次解码和一致的选择/错误结果；DataStore 事务及连接读取保持严格校验。
- Android `CertificateFiles` 将文件选择器 URI 有界复制到私有目录，每份最多 1 MiB、权限 0600；配置持久引用、暂存和活动连接共同持有文件。`ProfileStore` 的唯一实例串行提交与清理，原生连接退出后才释放最后的引用。失败导入清理新文件，导出和导入不携带本机文件路径；保存、删除和忘记证书成功后界面才完成操作，失败保留草稿。
- Android 应用统计由 `AppTrafficCollector` 管理采样需求，`AndroidTrafficStatsProvider` 只负责系统查询；页面可见且前台、未手动暂停时才启动采样。应用列表复用 UID，按缓存时限刷新；查询、重置和排序在后台执行，返回页面重建速率基线。
- 本轮不迁移旧客户端 schema；全新创建配置或导入公共连接信息。固定证书指纹仍必须通过证书有效期检查，不能以公钥相同绕过过期/尚未生效检查。
- 同一来源的认证路径变化可以保留绑定；服务器主机或端口变化需要清除原凭据与信任。其他产品的历史数据不隐式迁移。
- 普通服务设置同时提交 ocserv 与受管防火墙。项目拥有四个命名段的完整定义，其他管理员规则不属于该模块。
- `backend.snapshot` 在创建 UCI 游标前读取原始 ocserv / firewall 文件，全部字段读取后再次按内容核对；并发变更返回 `stale_revision`，I/O 错误保持原错误，不带着不一致数据继续查询或修改。读取不新增锁、临时文件或自动重试；与配置写入共用原有快照入口。`logic.revision` 依次消费原始文件与分隔符，避免拼接最多约 1 MiB 的中间字符串。校验后发生的写入仍由提交时的修订和事务检查处理。
- 请求入口、普通/隔离恢复记录和 occtl 会话响应在 jsonc 解码前复用 `logic.json_has_null` 拒绝字符串外的 `null`，避免显式字段或数组末尾被直接丢弃。当前数据契约不包含 nullable 字段；恢复记录以 `false` 表示原值不存在，省略可选字段仍遵循各自定义。扫描通过字符串查找跳过正文，正确处理引号与转义，不复制整个快照；解码后的结构校验仍保留。异常恢复记录在写入或服务操作前失败，在线查询报错，无法确认会话撤销时回滚账号事务。
- `logic.validate_settings` 在任何写入前复用 `logic.array` 检查 DNS（1–3 项）及分流路由（1–128 项）的完整结构；路由在输入预算内按数字地址与前缀去重，保持首次出现顺序。校验和归一化不依赖 UCI，后台事务仅消费完整结果；重复路由不触发无效配置提交或重启。
- 普通服务事务使用固定目录 `/etc/ocserv/easy-transaction`，候选文件各不超过 256 KiB；后台、下次修改和启动均可恢复未完成的文件替换。开机恢复只恢复持久配置，跳过随 `/var` 消失的派生密码文件，随后由启动渲染重建；运行中恢复仍核对密码文件的外部修改。恢复失败保留记录并阻止正常开机启动。
- `ocserv.runtime` 在写入正式文件前生成完整配置和账号、执行配置预检并核对 UCI 修订。普通写入失败恢复两个旧运行文件，失败不进入 procd 启动。设置与隔离共用预检作用域，所有正常异常路径清理候选文件。旧 shell 渲染、追加账号与 LAN 自动改写实现已移除。
- `configuration.with_stage` 在共享租约内创建、校验、加载并清理固定 UCI 候选及 delta 文件。普通保存与代理接入均在此作用域内执行，包括恢复记录创建和事务收尾；后台不再提前准备代理候选，也不为恢复回滚临时游标。持久恢复只使用 journal 和原始快照，候选清理不会删除它们。预检另用受保护的作用域清理 `check.conf` 和 `check.passwd`；进程被强制终止时不保证执行清理，固定临时路径可被后续操作覆盖，重启清空 `/var/run`。
- 普通恢复清单必须是连续数组，最多 7 个唯一目标；完整检查后才恢复文件。恢复计划只保留待写回的原始内容，已恢复文件不进入计划，也不保留当前候选内容；重复恢复不增加文件写入。
- 隔离记录为 schema 4，`started` 始终为布尔值。`guard_state` 校验清单、UCI 值、配置快照、固定文件目标和状态展示字段；坏记录在配置写入或服务命令前被拒绝，状态显示恢复异常。旧格式不迁移，升级前须用原版本关闭隔离并完成恢复。
- `storage.read` 只在 ENOENT 时返回 `nil`，存在的空文件返回空字符串，其他打开或读取错误抛出 `read_failed`。隔离状态读取采用同一实现，预算为 2 MiB；空白状态必须通过解析拒绝，不能视为未开启。原子写入通过 nixio 的零起始偏移重试部分写入，复用原字符串。
- `storage.scan_lines` 按最多 4 KiB 分块扫描，单行最多 4 KiB，支持跨块行和无换行的末行；调用方指定总字节预算，回调返回 `false` 可提前结束。不存在返回 `nil`，读取、预算或回调错误向上传递，结束及异常均关闭句柄。`proxy` 每次先收集规则目标，再统一扫描 TCP/UDP 的 IPv4/IPv6 表，每张表最多 4 MiB；只保存目标端口，全部找到后跳过余下内容及同协议的下一张表。没有目标则不读取连接表。已观测端口为真，只有两张表都完成扫描才能判定未发现端口为假，其他情况为未知；检测不新增缓存或常驻任务。
- 安装器首次网络初始化保存候选和原始配置；VPN-only 事务另有状态、确认和恢复记录。检测到后续修改时保留现场，不用旧快照覆盖。
- 后台偏好写入、系统网络设置等待和查询缓存各自封装为单一模块；UI/控制器负责组合，新增字段、平台策略和恢复职责应沿这些边界扩展。Windows 空闲事件兜底计时器为 1 秒，活动会话为 250 毫秒；窗口隐藏或最小化时停止请求界面统计。Apple 核心回调使用局部自动释放池，重连临时对象不再等待整个隧道结束才回收。
- Linux 收到完整认证结果后异步发送 `QUIT`，最多等待 1 秒，超时或写入失败终止助手；失败及取消直接终止。进程退出和管道操作完成后才回调并释放请求，期间新请求仍受单槽约束。收尾期间取消仍拒绝返回凭据，助手提前退出会取消未完成的写入；计时器只在收尾时存在，不限制用户填写认证表单的时间。
- 查询缓存每个名称使用固定的 JSON 快照和 32 字节随机代次标记。刷新及显式失效先原子替换标记；查询只发布自己的代次，读取快照后再核对标记。旧查询即使在失效后的重命名窗口写入，也不会被后续请求接受。无需持有配置租约或等待其他查询；失败时返回实时结果，标记和快照均可丢弃，不迁移旧缓存格式。
- 在线缓存格式 3 同时保存完整列表和小摘要，共用 5 秒有效期、稳定内容版本及独立失效代次。摘要命中不解码完整列表，不写文件或执行 occtl。独立查询锁最多等待 5 秒合并刷新，配置写锁与失效操作不等待查询锁；异常仍回退有时限的实时查询。页面每 3 秒取摘要，仅账号页在内容版本变化时获取列表；较旧列表不能覆盖新摘要，最多立即补读一次。回归分别检查完整结果、摘要零大文件读取、零写命中及并发等待复用。
- 页面同时跟踪请求期间的新编辑和请求开始前已有的未保存表单。后台完整刷新与隔离确认在表单结束后执行，合并多次状态变化；等待期间不更新表单修订号，避免用新修订号提交旧字段而绕过冲突检查。成功保存和显式刷新清除延后刷新状态。
- 每个只读查询槽最多保留一个请求及控制器。取消先释放归属再中止 fetch，新请求可立即开始；旧成功、异常和 finally 均检查归属，不能发布或清空新请求。完整刷新、状态轮询和只读弹窗复用同一实现，配置提交保留独立的超时与结果处理。
- 账号与在线列表先筛选并截取当前页，再调用行工厂，不为其他页创建节点或事件闭包。其他页数据变化不重建当前行；计数、分页按钮及状态通知仅在值变化时更新。完整刷新重新创建列表以重新应用权限，保留搜索与有效页码；切换标签释放旧列表引用。新模块随 LuCI 资源打包，JavaScript 与 CSS 禁用 SDK 改写并逐文件核对安装包摘要。
- `table.js` 用当前页的 Map 保存唯一键、行节点和序列化签名；新页完成后释放旧页条目。变化行重新调用行工厂，操作闭包读取最新记录；不变化的行直接保留或移动。焦点只恢复到相同记录的同一控件，记录消失或控件不可用时回到滚动容器。账号以 UCI ID、连接以 occtl ID 为键，后端在归一化后拒绝重复连接 ID，不发布部分结果。
- 标签选择统一经 `selectTab`，当前标签再次激活不触发渲染或清除编辑标记。页面负责标签与内容的 ARIA 关联、单个 Tab 停靠点及方向键导航；没有额外监听器注册周期、请求或定时器。
- 账号在线状态由 `app.js` 按完整登录名称、区分大小写汇总当前在线快照；UCI 账号 ID 与 occtl 会话 ID 各有用途，不互相匹配。每次更新只扫描一次会话并就地更新至多 50 个账号标记，无额外请求、定时器或行重建。查询或 HTTP 轮询失败时标记未知并隐藏旧连接操作；被取消或过期的请求不改变状态。
- 在线汇总仅在账号列表可见时执行，进入列表时从最新状态重建；离开标签时释放汇总对象。系统维护模块只组合静态说明和剪贴板交互，不持有服务状态或权限。
- 普通命令仍捕获最多 128 KiB 输出。`process.run` 的可选流式消费者允许显式指定总字节预算，不累计输出；消费者拒绝或抛错复用进程组终止和回收路径。`occtl` 每次最多消费 64 MiB、每条最多 64 KiB、嵌套最多 32 层；在线最多 4096 条，缓存会话最多 65536 条，分别限时 4 秒和 5 秒。只保留裁剪后的在线字段，撤销核实不保留条目。完整数组结束及命令成功后才发布；发现目标仍有会话时提前终止核实并返回失败。在线缓存独立限制为 4 MiB；名称/IP/时间最多 64 字节、状态最多 32 字节，清除控制字符并保留 UTF-8 边界。容量覆盖 4096 条记录及 JSON 转义，其他缓存和持久配置继续使用默认 256 KiB 上限。
- `process.run` 分别跟踪主进程回收与输出 EOF，两者都完成才返回退出码；EAGAIN 仅表示暂时无数据。主进程已回收时不再调用 waitpid，后代持有的管道仍受原时限及预算约束，失败只终止剩余进程组。`occtl` 的显示裁剪在 UTF-8 边界回退，保持 64/128 字节预算；短字段直接复用，长字段只检查截断处，不遍历全文。IPv4 经过字段归一化后为空时才选用 IPv6。
- 服务端打包按当前源码清单自动核对所有 Lua 运行模块的摘要，删除手工重复的模块名称列表；新增模块随源码包分发并自动进入安装包审计。

## 验证与清理

先运行相关纯逻辑和边界回归，再运行目标平台编译、原生认证/脚本/窗口回归及包审计。服务端安装恢复测试包含提交后和收尾前的进程中断。浏览器夹具由 `server_fixture.lua` / `guard_fixture.lua` 独立构造，不在启动时重跑回归；列表需求、迟到完成与摘要代次由独立浏览器用例覆盖。`certificate_material_tests.py` 用真实证书和 certtool 检查信任链、地址及轮换；其他 OpenWrt 接口由隔离夹具模拟。

Apple unsigned 构建、Android JUnit、NetworkManager IPC 和模拟 UCI 均不能替代真实设备的签名授权、转发、睡眠、网络切换及长期测试。构建证据和设备证据分别记录在 `VALIDATION.md`，不把编译成功写成连接成功。

`regression.yml` 在 PR 和 main/codex 分支推送时执行轻量逻辑、真实浏览器、Linux 编译及 Apple 存储回归。完整构建仍由各平台工作流执行，不在自动回归中发布发行版。Android 图表仅在被订阅时生成历史快照，删除无效的固定公网/客户端隧道地址延迟探测；WakeLock 保留到真机睡眠和耗电测试提供依据后再调整。

使用 `scripts/clean-workspace.ps1` 先预览，再以 `-Apply` 清理。删除失败时把剩余内容集中移至 `artifacts/manual-delete` 并记录来源；`-QuarantineOnly` 可直接归集而不删除。跟踪源码、运行进程、符号链接及路径边界会先检查，隔离目录不能与清理目标重叠。发行包、备份、私有配置及证据默认保留；清理测试输出前先归档验证摘要。`-DeepClean` 另清工具链/依赖，下次须重建。受管 CA 仅在成功提交后回收，Linux 以已提交候选保护新 CA，避免 libnm 缓存更新延迟造成误删。

平台策略优先放在可独立验证的模块，界面只组合策略和平台调用。新增模块必须进入对应源码包与安装包审计；故障回归应覆盖对外行为，不能仅断言适配脚本包含某段文本。更改生成工程应修改固定上游的适配配方，不提交构建缓存。

## 本轮职责收敛

- `online_query.lua` 负责在线列表/摘要查询与缓存投影；`client_distribution.lua` 负责平台信任能力、保存验证和公共配置导出，`backend.lua` 保留应用编排。接口版本为 4，移除旧字段，不添加适配层。
- `StorageObservation` 是不依赖 Android UI 的存储观察恢复策略。配置与设置共用有界 IO 重试和显式重载；严格连接快照继续直接读取持久数据，错误占位不能启动连接。
- `TunnelDiagnostics.swift` 统一 Apple 扩展诊断字段白名单、大小限制和超时；应用层负责连接代次校验及文件导出。
- Linux 的异步激活完成处理与 libnm 回调解包分离，可直接测试取消、空结果和过时代次，GTK 不参与状态恢复。
